# webteam-research-and-reference-transfer

## Purpose and activation
Research design references and responsibly adapt transferable principles without cloning brands or losing project identity.

**Activate when:** User requests reference website/repo, design direction research, externally inspired interface, accessibility/design reference comparison.

**Required inputs:** Reference URL(s), scope, licensing, user-stated desired qualities, target PRODUCT/DESIGN and current implementation.

## Professional workflow
1. Confirm legitimate access to source/screenshots and record URL/revision/date; inspect only material relevant to the UI task.
2. Decompose reference into transferable characteristics: hierarchy, interaction, composition, token relationships, content organization, density, not branded artwork and source code.
3. Identify required assets/fonts/licenses and technical constraints; avoid unauthorized copying of protected designs/code.
4. Compare target project Design DNA, information needs, locale, accessibility and performance; reject mismatched concepts.
5. Propose 2–3 adaptation ideas with measurable task benefits, cost, and potential tradeoffs.
6. Build original implementation under target project tokens and contracts, with review/approval for any major visual migration.
7. Validate through screenshots and actual flows rather than asserting similar taste.

## Known anti-patterns
Pixel cloning of identifiable competitor pages, scraping paid/private references, import of untrusted executable package without review, replacing project brand without asking.

## Deliverables
Reference ledger, adaptation rationale, source permissions, proposed concepts and resulting visual evidence.

## Quality gate / Definition of Done
Design is original, appropriate and provenance is documented.

## Coordination, boundaries and recovery
Owner: `webteam-designer`. Coordinate with Product for user intent and truthfulness, Frontend for faithful implementation, QA for reproducible functional/visual evidence, Accessibility for WCAG checks, and Reviewer for critical change approval. Read relevant `docs/PRODUCT.md`, `docs/DESIGN.md` and `docs/design/DESIGN_DNA.md` selectively; do not load every design skill at once. For a pre-existing project, preserve confirmed style and behavior by default. For a missing browser, mark actual rendering unverified; do not fabricate visual test results. Escalate changes to brand, permissions, production UX or consequential data displays.

## Task example
Given a scoped request involving research and reference transfer, state source evidence and user goal, make one bounded design decision, produce implementable design contracts and request actual browser review when available.

## Review checklist
- [ ] Decisions are anchored to the target audience and real workflows.
- [ ] No invented facts or unlicensed reference copying.
- [ ] Components have keyboard, mobile, error/empty and content-extreme states.
- [ ] New identity is distinctive without gratuitous effects.
- [ ] Existing Design DNA remains intact unless approved.
- [ ] Tests, screenshots and approvals are described truthfully.
