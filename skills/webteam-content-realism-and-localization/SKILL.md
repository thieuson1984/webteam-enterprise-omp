# webteam-content-realism-and-localization

## Purpose and activation
Produce credible interface content, contextual microcopy and localization-ready states without fake dashboards or placeholder-driven design.

**Activate when:** Content-heavy UI, empty states, education/enterprise systems, localization, AI-produced placeholder copy or confusing error messages.

**Required inputs:** Domain glossary, user tasks, approved facts/data, locale requirements, voice guidelines, legal/privacy constraints.

## Professional workflow
1. Build a source-of-truth ledger for any numbers, testimonial, claims, sample records, brand names and images; label mocks and synthetic examples visibly.
2. Draft meaningful headings, label/description/action/error/success/empty-state microcopy for actual flows, not Lorem Ipsum in a finished deliverable.
3. Provide plain-language errors explaining what happened, how to recover and where to get help without revealing security internals.
4. Test copy expansion (Vietnamese and longer translations), truncation, dates, currency and number formatting; preserve business meaning.
5. Choose data density based on user needs: operational tables need information, not empty cards; landing content needs specific value and proof.
6. Validate grammar, terminology, tone, accessibility naming, truthful copy and responsive layout.
7. Document unresolved facts and obtain confirmation rather than inventing customers, quotes, charts, certificates or compliance badges.

## Known anti-patterns
“Unlock your potential” filler; fake 24.7% growth cards; fabricated schools/teachers or sales figures; silent empty states; all-caps labels without context.

## Deliverables
UI copy deck, terminology guide, sample-data provenance, localization QA matrix.

## Quality gate / Definition of Done
Every interface is understandable with authentic or clearly synthetic content and remains stable when translated.

## Coordination, boundaries and recovery
Owner: `webteam-designer`. Coordinate with Product for user intent and truthfulness, Frontend for faithful implementation, QA for reproducible functional/visual evidence, Accessibility for WCAG checks, and Reviewer for critical change approval. Read relevant `docs/PRODUCT.md`, `docs/DESIGN.md` and `docs/design/DESIGN_DNA.md` selectively; do not load every design skill at once. For a pre-existing project, preserve confirmed style and behavior by default. For a missing browser, mark actual rendering unverified; do not fabricate visual test results. Escalate changes to brand, permissions, production UX or consequential data displays.

## Task example
Given a scoped request involving content realism and localization, state source evidence and user goal, make one bounded design decision, produce implementable design contracts and request actual browser review when available.

## Review checklist
- [ ] Decisions are anchored to the target audience and real workflows.
- [ ] No invented facts or unlicensed reference copying.
- [ ] Components have keyboard, mobile, error/empty and content-extreme states.
- [ ] New identity is distinctive without gratuitous effects.
- [ ] Existing Design DNA remains intact unless approved.
- [ ] Tests, screenshots and approvals are described truthfully.
