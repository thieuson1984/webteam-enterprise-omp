# webteam-landing-and-marketing-experience

## Purpose and activation
Create distinctive product-specific landing and marketing pages with editorial storytelling, credible proof and conversion-focused layouts.

**Activate when:** Marketing homepage, product launch, pricing, feature showcase, campaign, public education/institution site, signup funnel.

**Required inputs:** Positioning, target audience, differentiator, true benefits, approved brand and proof, actual CTAs, localization, conversion constraints.

## Professional workflow
1. Define one core promise with a concrete audience and outcome. Write honest copy before creating hero decoration.
2. Build narrative arcs (problem → product proof → workflow → benefits → trust → CTA) only as relevant; omit generic repeated feature blocks.
3. Explore 2–3 genuinely different editorial compositions for major surfaces; choose one aligned to product identity and available visual assets.
4. Use photography/illustrations only with rights and product relevance; prefer authentic product screenshots over stock silhouettes or random floating UI.
5. Design purposeful navigation, pricing/FAQ/proof interactions, readable long-form content, mobile CTAs and performance-aware hero assets.
6. Validate claims (no invented endorsements, user counts or awards), actual clickable actions, accessibility, speed and SEO metadata.
7. Conduct substitutability test: if brand names disappear, can users tell why this product is different? Refine content and hierarchy rather than layering gradients.

## Known anti-patterns
Universal gradient hero + triple feature cards + fake logos + oversized testimonials; unrelated illustrations; false scarcity; decorative blank whitespace.

## Deliverables
Messaging hierarchy, approved content inventory, responsive page compositions, asset ledger and conversion state specifications.

## Quality gate / Definition of Done
Memorable yet credible product story, functional CTA flow, no fabricated proof and good performance on modest mobile devices.

## Coordination, boundaries and recovery
Owner: `webteam-designer`. Coordinate with Product for user intent and truthfulness, Frontend for faithful implementation, QA for reproducible functional/visual evidence, Accessibility for WCAG checks, and Reviewer for critical change approval. Read relevant `docs/PRODUCT.md`, `docs/DESIGN.md` and `docs/design/DESIGN_DNA.md` selectively; do not load every design skill at once. For a pre-existing project, preserve confirmed style and behavior by default. For a missing browser, mark actual rendering unverified; do not fabricate visual test results. Escalate changes to brand, permissions, production UX or consequential data displays.

## Task example
Given a scoped request involving landing and marketing experience, state source evidence and user goal, make one bounded design decision, produce implementable design contracts and request actual browser review when available.

## Review checklist
- [ ] Decisions are anchored to the target audience and real workflows.
- [ ] No invented facts or unlicensed reference copying.
- [ ] Components have keyboard, mobile, error/empty and content-extreme states.
- [ ] New identity is distinctive without gratuitous effects.
- [ ] Existing Design DNA remains intact unless approved.
- [ ] Tests, screenshots and approvals are described truthfully.
