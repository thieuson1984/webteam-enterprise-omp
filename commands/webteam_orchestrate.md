## Arguments and outcomes

- `--mode=plan` (**default**): create a scoped in-chat task charter, owner/risk matrix and DAG; do **not** modify application files.
- `--mode=run`: execute only authorized, bounded tasks through verified MAIN/task topology; ask separately for material writes and high-risk/external effects; delegate writing to named owner, then independent QA and Reviewer.
- `--mode=verify`: independently check actual task status and delivery evidence; does not assume child completion from planned DAG.
- `--dry-run`: no application source writes, external effects, installs, migrations or prod tests; use fake/synthetic fixtures for task routing if separately authorized.
- Unknown flags or ambiguous scope: reject or request correction. `--budget` cannot increase the user's approved model/provider spending.

## Orchestration protocol

1. Verify `cwd`, project and Git revision/dirty files, user goal, supported OMP `task` interface and 16 agent definitions; inspect `task.disabledAgents`, spawn/recursion policy and effective tools if available. An installed file is not dispatch proof.
2. Risk C1–C5, select the minimum specialists. For routine single-file tasks use MAIN/one owner. For cross-domain tasks build a finite dependency DAG with unique task IDs, charter, source/contract ownership, budget and evidence gates.
3. Determine MAIN→specialists vs MAIN→Orchestrator→specialists **based on effective task depth**; never recursively spawn beyond verified limit. Subagents can inherit headless tools with permissive approval mode: user consent and scope must be enforced by MAIN before dispatch.
4. Start independent tasks only when write sets are disjoint; wait for asynchronous child completion and reconcile API/data/UI contracts at the same source revision.
5. Call independent Reviewer on meaningful changes, QA/Accessibility/Security/Performance on applicable risks. Do not let the author approve own high-risk patch. Do not run uncontrolled quality loops or councils.
6. Stop on unapproved side effects, unknown prior mutation, overlapping writers, critical UNVERIFIED checks or exhausted budget. Return charter, DAG, actual child IDs/models when observable, checks/results, changed paths, blockers and precise next action.
